# RP-Hand DexPilot 启发式 6DOF 重定向设计

## 目标

在不改变当前稳定映射结果的前提下，为 RP-Hand Gesture 增加第二套可切换的实验映射算法。新算法参考 DexPilot 的相对指尖向量、接触目标和时序正则思想，针对只有 6 个主动自由度的 RP-Hand 做轻量适配，用于改善拇指对掌、捏合和多指协同。

Electron GUI 提供两个映射算法：

- `轻量映射（稳定）`：当前已经过真机标定的算法，保持为默认选项。
- `DexPilot 6DOF（实验）`：本设计新增的纯 NumPy 有界优化算法。

本阶段不直接引入官方 `dex-retargeting`、Pinocchio 或 NLopt，也不承诺复现人手缺失在硬件上的 DIP 独立弯曲、手指侧摆等自由度。

## 设计原则

1. **稳定模式零回归**：现有 `GestureMapper` 的输入、标定值和输出保持不变。
2. **实验逻辑独立**：DexPilot 模式位于独立模块，通过统一策略接口接入运行时。
3. **安全控制高于算法**：急停、恢复、暂停、指令发送和安全姿态不属于任何映射策略，切换算法不能绕过它们。
4. **切换无跳变**：新策略从当前实际目标值初始化，首帧不得突然跳到另一组关节位置。
5. **依赖轻量**：实时计算仅使用 NumPy，保持 Windows 安装包可部署性。
6. **诚实命名**：界面和文档使用 `DexPilot 6DOF（实验）`，明确它是受 DexPilot 启发的低自由度适配，不是官方库的完整实现。

## 为什么不直接使用完整官方库

官方 `dex-retargeting` 通过机器人 URDF、正向运动学和数值优化匹配人手与机器人手的空间关系，适合拥有较多独立关节并具备准确模型的灵巧手。RP-Hand 当前只有以下 6 个主动控制通道：

- `thumb_bend`
- `thumb_rotate`
- `index_finger`
- `middle_finger`
- `ring_finger`
- `pinky_finger`

人的手部姿态信息远多于 6 个维度。即使完整优化器获得全部 MediaPipe 关键点，也只能在多个冲突目标之间折中，无法创造硬件不存在的执行器。直接引入官方库还会增加 URDF 精度、关节顺序、Pinocchio/NLopt 兼容性和安装包体积等风险。

因此第一阶段复用其最适合当前硬件的目标构造方式，在 6 维关节空间内做小型、确定性的加权投影。若真机 A/B 测试证明空间目标明显优于当前映射，再单独评估完整官方后端。

## 架构

### 策略接口

新增运行时重定向协调器，持有两个互不依赖的策略：

```text
HandObservation
      |
      v
RetargetingCoordinator
      |-- StableRetargetingStrategy -> 现有 GestureMapper
      `-- DexPilot6DofStrategy      -> 新增 6DOF 优化器
      |
      v
6 个关节目标值
      |
      v
现有暂停 / 发送 / 急停 / 驱动链路
```

策略统一接收 `HandObservation`，输出以现有关节名称为键的目标位置。稳定策略只是当前 `GestureMapper` 的薄适配层，不重写其公式。实验策略内部产生归一化的 6 维向量，再通过共享的关节范围投影器转换为当前驱动使用的整数目标值。

`main.py` 只负责把观测传给协调器以及处理运行时命令，不保存几何公式、优化权重或 GUI 状态。

### 模块边界

- `retargeting_strategy.py`：策略协议、协调器、模式切换和异常回退。
- `dexpilot_6dof.py`：掌心坐标、特征构造、接触状态和 6DOF 加权投影。
- `gesture_mapping.py`：保留现有稳定映射；仅在测试保护下提取无业务含义的关节范围转换帮助函数。
- `runtime_control.py` / 现有桥接层：增加映射算法切换命令，不改变行为模式和安全状态。
- `runtime_telemetry.py`：上报当前映射算法和实验策略回退状态。
- `electron/renderer`：显示“映射算法”下拉菜单并与运行时状态同步。

## DexPilot 6DOF 算法

### 1. 掌心局部坐标

输入优先使用 MediaPipe 的 21 个世界坐标关键点。以腕点为原点：

- 横轴由小指 MCP 指向食指 MCP；
- 纵轴由腕点指向中指 MCP，并消除横轴分量；
- 法向轴由前两轴叉乘得到；
- 所有长度除以食指 MCP 与小指 MCP 的掌宽。

该变换消除相机中的整体平移、手掌旋转和画面尺度影响。掌宽过小、坐标非有限值或坐标轴退化时，本帧实验策略判定为不可用。

### 2. 基础弯曲目标

五指继续使用完整骨链的指尖回缩量：

```text
chain = |MCP-PIP| + |PIP-DIP| + |DIP-TIP|
reach = |MCP-TIP| / chain
retraction = 1 - reach
```

每根手指使用独立的开合端点校准到 `[0, 1]`。拇指弯曲同时参考拇指骨链回缩和掌心到拇指尖的归一化距离；拇指旋转参考拇指尖在掌心局部坐标中的对掌方向。

### 3. 接触目标

计算拇指尖到食指、中指、无名指和小指尖的掌宽归一化距离。每个接触对包含两个阈值：

- `project_distance = 0.30`：距离进入该范围后激活接触目标；
- `escape_distance = 0.42`：已激活接触只有超过该范围才释放。

这段滞回避免手指在阈值附近抖动。多个接触同时出现时全部参与，但最近的接触获得最高权重。不同目标手指对应可配置的拇指旋转目标，使拇指从食指方向逐步移动到小指方向。

### 4. 有界加权投影

令归一化关节向量为：

```text
q = [thumb_rotate, thumb_bend, index, middle, ring, pinky]
```

该顺序不是展示层约定，而是 DH116 的电机通道契约：第 1 轴为拇指外展/对掌，
第 2 轴为拇指屈曲。映射器初始化时必须校验配置顺序，避免两个看似合理的
拇指特征被发送到彼此的电机。

真机测试进一步确认，第 1 轴与其余轴一样使用 `[0, 10000]`：完全张手时必须输出
`0`。此前把通道交换问题误判为电机极性问题，会让张手姿态输出 `10000` 并使拇指
错误立起。通道顺序与电机极性必须分别由回归测试约束。

MediaPipe 的左右手标签继续保留在观测结果中，但当前六自由度映射只使用弯曲度、
无符号夹角和指尖距离，因此左右镜像姿态应输出相同的规范化目标。只有接入左右两只
不同硬件手，或增加有符号对掌、手腕姿态和横向展指后，才由 handedness 统一符号。

每帧求解以下 6 维加权最小二乘问题：

```text
min  ||W(Aq - b)||^2 + temporal_weight * ||q - q_previous||^2
 s.t. 0 <= q <= 1
```

`A` 和 `b` 由基础弯曲目标、拇指对掌目标和已激活的指尖接触目标构成。问题规模固定，使用 `numpy.linalg.solve` 求解正规方程后裁剪到 `[0, 1]`，不引入通用迭代优化器。

`temporal_weight` 默认取 `0.20`，用于抑制 MediaPipe 关键点噪声导致的拇指关节跳动。切换到实验模式时，`q_previous` 从当前稳定模式的输出反算初始化，而不是从零开始。

## 配置

新增配置保持实验参数可调，但默认值可直接运行：

```yaml
hand:
  retargeting_strategy: stable
  dexpilot_6dof:
    temporal_weight: 0.20
    project_distance: 0.30
    escape_distance: 0.42
    base_weight: 1.0
    contact_weight: 2.5
    opposition_targets:
      index: 0.35
      middle: 0.52
      ring: 0.70
      pinky: 0.88
```

现有 `finger_retargeting` 与各指开合标定继续属于稳定模式。实验模式拥有独立配置，修改它不会改变稳定模式真机效果。

## GUI 与运行时协议

Electron 右侧控制栏将原来的单项“控制模式”改为“映射算法”：

- `轻量映射（稳定）`
- `DexPilot 6DOF（实验）`

运行时新增独立命令，例如 `retargeting_stable` 与 `retargeting_dexpilot`。该状态不得复用当前的 `mode_mirror`、`mode_gesture` 或 `mode_rps`，因为“行为模式”和“映射算法”是两个不同概念。

遥测状态增加 `retargeting_strategy`。GUI 以 Python 运行时返回的状态为准，后端拒绝切换或回退时不能只在前端显示成功。

## 安全、异常与回退

- 急停状态下可以选择算法，但不会发送新关节目标。
- 暂停或关闭“指令发送”时，算法可继续计算预览值，但不写入 CAN-FD。
- 切换算法会清空接触滞回状态，并从当前目标初始化时间正则状态。
- 掌心坐标退化、输入包含非有限值、线性方程求解失败或输出越界时，本帧使用稳定算法结果。
- 连续回退原因通过遥测提供给 GUI 和日志，但不弹出阻塞实时控制的模态窗口。
- 所有实验输出仍经过现有关节上下限裁剪，实验算法无权更改驱动频率、电流或安全姿态。

## 测试

### 单元测试

- 掌心特征对整体平移、旋转和尺度保持不变。
- 张开手输出接近各通道开端，握拳输出接近闭端。
- 单独弯曲一根手指不会显著驱动无关手指。
- 拇指分别接近食指、中指、无名指和小指时，规范化旋转目标与投影后的原始
  电机位置均单调增加。
- 接触滞回在两个阈值之间保持状态，不逐帧闪烁。
- 所有输出有限且位于 `[0, 1]`，异常输入回退稳定算法。
- 相同输入下稳定模式输出与迁移前完全一致。
- 模式切换首帧变化受限，不从零位跳变。

### 集成测试

- Electron 下拉菜单发送正确命令并根据遥测同步选项。
- Python 桥接层可在两种策略之间往返切换。
- 急停、恢复、暂停和指令发送状态在切换前后保持正确。
- 无摄像头、丢失手部和退化坐标不会导致进程退出。

### 真机 A/B 验证

使用同一光照、距离和手掌朝向，依次比较：

1. 张开手与握拳；
2. 五根手指分别独立闭合；
3. 拇指依次接触食指、中指、无名指和小指；
4. 捏合保持时的抖动；
5. 快速开合时的延迟和是否出现跳变。

只有在实验模式至少改善拇指对掌或多指接触，同时没有破坏急停、稳定性和基本开合时，才考虑将其带入后续版本。稳定模式始终保留为回退选项。
