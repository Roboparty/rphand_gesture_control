# SAFE-01 至 SAFE-03 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 RP-Hand 真机控制链路补齐确定性资源清理、丢手看门狗、紧急停止、指令约束和反馈故障监控，同时保持现有识别与关节映射行为不变。

**Architecture:** `app_runtime.py` 只负责按确定顺序持有和关闭驱动、摄像头、识别器与窗口；`control_safety.py` 提供与 OpenCV、MediaPipe 和真实 SDK 无关的状态机、限幅器和反馈监控器。`main.py` 只编排这些组件，真实驱动通过扩展后的 `BaseHandDriver` 暴露 `stop()` 与 `get_health()`。

**Tech Stack:** Python 3.12、pytest、OpenCV、MediaPipe 0.10.14、PyYAML、LHandPro CAN-FD SDK。

- [ ] **Step 1: 实现幂等 RuntimeResources**

```python
class RuntimeResources:
    def __init__(self, destroy_windows):
        self.driver = None
        self.camera = None
        self.recognizer = None
        self._destroy_windows = destroy_windows
        self._closed = False

    def __enter__(self):
        return self

    def __exit__(self, exc_type, exc, tb):
        self.close()

    def close(self):
        # driver -> camera -> recognizer -> windows
        # 每一步独立捕获异常，确保后续清理仍执行。
        if self._closed:
            return
        self._closed = True
        for resource, method_name in (
            (self.driver, "disconnect"),
            (self.camera, "release"),
            (self.recognizer, "close"),
        ):
            if resource is not None:
                try:
                    getattr(resource, method_name)()
                except Exception as exc:
                    print(f"资源清理失败: {method_name}: {exc}")
        self._destroy_windows()
```

- [ ] **Step 2: 将 main 全部初始化纳入上下文**

`main(argv=None)` 使用 `parse_args(argv)`，驱动连接失败和摄像头失败返回 1；正常退出返回 0。所有 return 都位于 `with RuntimeResources(destroy_windows=cv2.destroyAllWindows)` 内。

- [ ] **Step 3: 让真机驱动清理部分连接状态**

`LHandProDriver.disconnect()` 在存在 controller 时尝试停止和断开，不以外层 `_connected` 为唯一条件；`connect()` 捕获异常时立即调用幂等清理。

- [ ] **Step 1: 实现 TrackingState、SafetyDecision 和 TrackingWatchdog**

状态包含 WAITING、TRACKING、GRACE、SAFE_RETURN、SAFE_HOLD、STOPPED。看门狗使用 monotonic 时间；`note_output()` 记录最后实际下发目标，安全返回从该目标插值到每个关节的张开位置。

- [ ] **Step 2: 扩展驱动停止接口**

```python
def stop(self) -> None:
    """立即停止电机运动，但保留 disconnect() 负责最终释放通信。"""
```

SimHandDriver 记录 stopped 状态；LHandProDriver 调用 controller.stop_motors()。

- [ ] **Step 3: 接入主循环**

每帧将识别得到的位置或 None 交给 watchdog；GRACE 保持最后目标，SAFE_RETURN 输出插值目标，STOPPED 调用 `driver.stop()` 并阻止后续下发。按 `e` 进入不可由空格恢复的 E-STOP，必须退出并重新启动程序才能恢复。

- [ ] **Step 1: 实现 CommandLimiter**

构造器接收每关节 range、初始安全位置、deadband、max_step、max_velocity 和 max_acceleration。`limit(target, now)` 先 clamp，再按实际 dt 限速和限加速度，最后应用单步限制与死区。

- [ ] **Step 2: 实现 FeedbackMonitor**

`note_send(success)` 记录连续发送失败；`evaluate(target, actual, alarms, now)` 检查报警、反馈缺失和持续位置误差，返回不可忽略的 fault code 与中文说明。

- [ ] **Step 3: 扩展驱动健康状态**

`get_health()` 返回形如 `{"alarms": {"motor_1": 0}, "currents": {"motor_1": 120}}` 的结构。仿真驱动返回零报警；真机驱动读取每个主动电机的当前报警与电流。读取失败返回 None，由 FeedbackMonitor 计数。

- [ ] **Step 4: 接入主循环和 HUD**

所有 watchdog 目标先经过 limiter，再下发驱动；主循环检查发送返回值并按配置周期读取反馈。故障触发 `driver.stop()`、禁止继续发送并在 HUD 显示 fault message。
